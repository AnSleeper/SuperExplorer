# 超级资源管理器（SuperExplorer）

为「看图、找图、整理素材」而生的 Windows 多面板资源管理器。当前阶段专注把"查看 + 最小必要操作"做到极致，长期目标是**彻底替代 Windows 资源管理器**，成为日常唯一使用的资源管理器。

> **⬇ 直接下载**：[Releases 页面](https://github.com/AnSleeper/SuperExplorer/releases) → 下载 `SuperExplorer-v0.1.1-win-x64.zip`，解压双击 exe 即用，免安装、免依赖（自带 .NET 运行时）。

## 为什么做这个软件

如果你有大量图片、GIF、视频素材散落在层层嵌套的目录里（比如 AI 绘图产出），用系统资源管理器整理会遇到几个烦：

- **一次只能看一个文件夹**。对照两个目录要开两个窗口来回切换，拖动窗口、对齐位置全靠手动
- **找图慢**。不知道哪张图在哪个目录，得一个个点开看
- **窗口一开多就吃内存**。素材整理时往往还在跑 AI 绘图等高负载程序，资源管理器不敢多开
- **整理容易出错**。移动、删除之后发现弄错了，没有后悔药

超级资源管理器针对这四点给出答案：

1. **多面板工作区** —— 一个窗口里同时打开最多 6 个文件夹，并排或网格排列，面板可拖拽换位，分隔条宽度自由调整，不用再开一堆窗口
2. **以看图为中心的浏览** —— 图片/GIF 缩略图、视频首帧、文本前 10 行内容直接铺在网格里，所有格式混排，翻目录就是翻图
3. **为长时间常驻而生的低内存设计** —— 这是本项目的**最高优先级原则，高于一切功能**：只渲染可视区域、缩略图按需加载，允许为省内存砍功能，绝不反之。实测空窗口约 108 MB，双面板开缩略图约 145 MB
4. **整理操作有安全网** —— 拖拽移动/复制真实生效，但删除只进回收站、支持 50 步 Ctrl+Z 撤销、同名文件自动加序号绝不覆盖、跨盘移动先复制成功再删源文件，弄错了随时反悔

## 设计理念

- **内存最小化是红线**：程序需要长时间挂在后台，同时机器上还跑着 AI 绘图等重负载任务，绝不能拖累主工作流。为此不用 Electron，选 WPF + 手写虚拟化渲染，视频只抽首帧不常驻解码器
- **宁缺勿滥**：在最基础的功能上一步步做加法，不做冗余功能（详见下方"明确不做"）
- **文件安全**：磁盘上的文件不因"整理"被偷偷移动或改名——只有你主动拖拽/删除才动真实文件，且一切操作可撤销
- **绿色便携**：单个 exe（自带运行时，免安装），设置和日志全部存在程序旁边，不写注册表、不占 C 盘
- **暗色护眼**：6 套暗色系主题（纯黑白为默认），字号 8 档、缩略图大小 8 档可调

## 功能一览

**浏览与找图**

- 图片 / GIF / 视频首帧 / 文本内容缩略图，所有格式混排（当前只显示图片、GIF、视频、文本、文件夹五类）
- 文件夹缩略图预览子文件夹里的第一张图（与系统资源管理器一致），文本文件显示前 10 行
- **搜索**（Ctrl+F）：在当前面板文件夹内递归搜索文件和文件夹，按需扫描不建索引、不吃内存，结果带相对路径
- 文件夹树懒加载、"设为顶层"（把任意文件夹设为树根，隐藏所有上级和同级，专注一个素材库）、常用文件夹收藏（全新安装默认把桌面加入常用）
- 可选**接管系统文件夹打开**：开启后双击文件夹用本程序打开（单实例转发到已运行窗口），启动时可接管资源管理器已打开的文件夹窗口；关闭开关即恢复系统默认

**整理文件**

- 跨面板 / 面板到左侧树 / 从系统拖入，拖拽移动真实生效；按住 Ctrl 拖 = 复制
- Ctrl+C / Ctrl+V 复制粘贴（复制图片时同时写入系统剪贴板的文件路径和图片内容，可直接粘贴进聊天、绘图软件）
- 右键 / Delete 删除（进回收站，可选确认弹窗）、右键新建文件夹、F2 或右键重命名（失焦自动保存）
- 50 步撤销栈：移动、复制、删除、重命名、新建文件夹全部可 Ctrl+Z；删除撤销 = 自动从回收站还原到原路径

**工作区与个性化**

- 并排 / 网格两种布局；奇数个面板时两列自动堆叠无空白区；面板顺序、各分隔条宽度全部记忆
- 从系统资源管理器拖文件夹进来：空工作区直接打开为面板，已有面板时弹窗选「复制进去 / 作为面板打开」，默认动作可在设置里改
- 关闭窗口默认**最小化到托盘**（托盘双击/右键恢复，可选直接退出）
- 6 套主题、字号阶梯、缩略图大小、左侧栏宽度、常用文件夹区高度，全部跨会话记忆
- 关闭前左侧树的展开状态下次启动原样恢复
- 全局异常捕获写日志，出问题不闪退

## 快捷键

| 按键 | 功能 |
|---|---|
| Ctrl+C / Ctrl+V | 复制 / 粘贴选中项 |
| Ctrl+Z | 撤销上一步文件操作 |
| Delete | 移入回收站 |
| F2 | 重命名选中项 |

## 暂不支持（计划中）

以下功能已在规划内但尚未实现：

- **程序内大图预览** —— 目前双击图片/视频调用系统默认程序打开；计划做成程序内按需解码、看完即释放的预览器
- **缩略图磁盘缓存** —— 目前缩略图为内存缓存，重启后需要重新提取；计划落盘缓存进一步降低常驻内存
- **全盘搜索** —— 当前搜索只在打开的面板文件夹内递归；全盘索引（SQLite 按需查询）在规划中
- **搜索内容**（按文件内容搜索）—— 目前只按文件名匹配
- **文件夹容量统计** —— 已实现但默认停用：递归扫描磁盘 IO 开销大，与低内存理念冲突；代码完整保留，需要时可一键恢复
- **多选批量操作** —— 当前为单选模型，一次操作一个文件
- **文件夹缩略图暗色适配** —— 目前使用系统原生预览（黄色调），与暗色主题略有色差，计划改为图片加灰框样式

## 明确不做

以下功能经确认**有意砍掉**，不是遗漏——与"宁缺勿滥"的迭代原则一致：

类型筛选、虚拟集合 / 智能文件夹、标签系统、右侧信息详情面板、疑似重复 / 已读徽标、网格 / 列表视图切换。

## 技术实现

- .NET 8 + WPF，**零第三方依赖**，单文件自包含发布（约 140 MB，自带运行时，免安装）
- **手写 Canvas 虚拟化网格**：只渲染可视区域内的卡片，滚出视区的卡片进复用池换绑数据；尺寸变化只重排不重建，预留滚动条宽度杜绝列数抖动死循环
- **缩略图管道**：图片按卡片实际宽度解码（避免小卡片解码大图浪费内存）；视频首帧与文件夹预览走 Windows Shell 系统接口（自带缓存），并发限制 3，失败项 60 秒后自动允许重试
- 撤销栈 50 步后进先出；回收站还原通过 Shell COM 按原路径匹配
- 分层架构：Controls（交互） / Services（文件系统、缩略图、撤销、设置、主题） / Models；未捕获异常写 `logs/error.log`

## 构建

需要 .NET SDK 8.0（Windows）：

```
cd src/SuperExplorer
dotnet publish -c Release
```

产出在 `bin/Release/net8.0-windows/win-x64/publish/`，可直接拷贝运行。设置保存在 exe 旁的 `data/settings.json`，日志在 `logs/`。

## 发布新版本（维护者）

1. 更新代码与 README 更新记录，bump `SuperExplorer.csproj` 的 `<Version>`，提交推送
2. 运行 `powershell -ExecutionPolicy Bypass -File tools\release.ps1`

脚本会自动编译、打 zip、创建（或更新）GitHub Release 并上传附件，发布说明从 git 提交记录自动生成。
